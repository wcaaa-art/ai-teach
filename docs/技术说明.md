# 技术说明与关键实现

## 项目目录交付项

项目完整目录见仓库根目录 [`README.md`](../README.md)。入口包配置、环境变量样例、Vite 配置、路由、Pinia 状态定义分别是 `package.json`、`.env.example`、`vite.config.js`、`src/router/index.js`、`src/stores/app.js`。十个页面（含首页、登录、账号中心）和公共组件位于 `src/views/` 与 `src/components/`；Express API 与 Agent 位于 `server/`。

## IndexedDB 表结构

版本为 `ai-teach-local / 8`（未登录的本地库）与 `ai-teach-user-<id> / 8`（登录后按账号分库），使用 `idb` 的 `openDB` 初始化。升级时只补建缺的对象仓库（`contains` 判断），老库数据不受影响。对象仓库均以 `id` 为主键，关键字段如下：

| 表 | 内容 | 关键字段 |
|---|---|---|
| `profile` | 当前学情档案 | `grade, subjects, weakPoints, dailyMinutes, targetScore, learningStyle, updatedAt` |
| `plans` | 当前与历史计划 | `name, subject, estimatedMinutes, priority, reviewTime, knowledgeTags, status, remindAt` |
| `focusSessions` | 番茄专注记录 | `planId, startedAt, endedAt, actualSeconds, completed, distractionCount` |
| `distractions` | 页面切换、视觉离岗及演示分心 | `type, createdAt, planId` |
| `feedbacks` | 任务完成度与掌握反馈 | `sessionId, planId, completion, mastery, note` |
| `assessments` | 专题摸底结果 | `grade, subject, chapterIds, masteryByChapter, source, createdAt` |
| `visualLogs` | 仅保存检测状态和误判记录 | `status, continuousAwaySeconds, createdAt, reason` |
| `conversations` | 独立答疑会话 | `title, messages, createdAt, updatedAt` |
| `quizFingerprints` | 题干指纹，用于周测 7 天去重（保留 14 天） | `stem, chapterId, mode, createdAt` |
| `quizResults` | 章节测试 / 周测结果 | `mode, questions, answers, selfGrades, score, maxScore, accuracy, createdAt` |
| `focusSuggestions` | 最近一次专注建议，固定 `current` 一条 | `recommendedMinutes, source, quizId, createdAt` |
| `examScores` | 学校考试多科成绩 | `examId, grade, subject, name, date, score, fullScore, createdAt` |
| `mistakes` | 错题归因（只存文字，不存题目照片） | `chapterId, chapterName, text, source, createdAt` |
| `quizDrafts` | 未交卷的答题草稿，固定 `current` 一条 | `answers, selfGrades, updatedAt` |
| `scannedPapers` | 试卷拍照识别后的 digital paper | `subject, questions, createdAt` |
| `reciteContents` | 背诵内容缓存（按「学科 + 计划名」幂等） | `subject, name, kind, content, source, confirmed, updatedAt` |
| `reciteSessions` | 背诵练习记录（逐句/逐词结果与耗时） | `planId, mode, total, correct, wrong, durationSeconds, startedAt` |
| `settings` | 用户偏好（固定存本地库，不随账号同步） | `cameraDefault, soundEnabled, ttsEnabled, darkMode, lowPerformance` |

图片帧、视频流、API 密钥和模型输入帧不进入 IndexedDB。`getRecentFocusContext(days)` 读取本地历史并由前端将聚合记录随 Agent 请求发送；视觉状态通过 `/api/agent/visual-status` 发送布尔在岗状态和持续秒数，不发送图像。

## 固定工具 Schema

工具名称、参数名与类型定义在 [`server/tools.js`](../server/tools.js)，是 DeepSeek Tool Calling 的唯一 schema 来源：

```json
[
  {"name":"calc_review_interval","parameters":{"last_study_time":"number","mastery_level":"0|1|2|3"}},
  {"name":"rag_knowledge_query","parameters":{"subject":"string","grade":"string","keyword":"string"}},
  {"name":"get_recent_focus_record","parameters":{"days":"number"}},
  {"name":"visual_monitor_get_status","parameters":{"is_present":"boolean","continuous_away_seconds":"number"}}
]
```

课程专题索引位于 [`server/curriculum.js`](../server/curriculum.js)，以教育部公开课程标准页面为来源说明，并整理成跨教材版本专题。它避免把不同出版社章节名称误说成全国统一目录。运行时 `/api/curriculum/subjects` 和 `/api/curriculum/chapters` 提供目录。系统不会抓取或复刻未经授权的商业题库。

真题检索层位于 [`server/rag/index.js`](../server/rag/index.js)：`scripts/build-rag-index.py` 离线把中考真题 PDF 按题切块，用 2~3 字滑窗建倒排表并压缩为 `server/rag/rag-index.json.gz`。查询时 BM25 打分，叠加关键词覆盖率、连续四字命中、学科与学段加权，高中语料在检索阶段直接跳过，两条结果去重后返回带《试卷名》出处的原文片段。`rag_knowledge_query` 因此同时返回课标知识点与真题解析，模型只可引用 1 条同类例题讲思路，不得整段抄题或直接给答案。运行时不需要向量数据库和 Python，替换为向量检索时只改检索实现，工具参数契约不变。

## DeepSeek 多轮工具调用

统一代理在 `server/agent.js` 的 `callDeepSeek`。每轮将 `tools` 及 `tool_choice: "auto"` 发给 OpenAI 兼容 `/chat/completions`；工具响应以 `role: "tool"`、原 `tool_call_id` 继续加入上下文。若模型消息包含 `reasoning_content`，会与 assistant 的 `tool_calls` 一起原样保留并回传到下一轮请求，避免思考模式下续轮缺字段。环境缺少密钥、请求失败、模型响应格式异常或工具轮次耗尽时，路由返回 mock，不让前端崩溃。

请求格式遵循 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/) 的续轮要求，以及 [DeepSeek Tool Calls 文档](https://api-docs.deepseek.com/guides/tool_calls/) 的 assistant/tool 消息配对方式。

运行密钥仅从服务端 `.env` 的 `DEEPSEEK_API_KEY` 读取。前端不读取该变量，也不调用 DeepSeek 域名。

## 内置系统提示词

完整提示词源文件：[`server/prompts.js`](../server/prompts.js)。

每条提示词的版本、用途与「必须包含的条款」登记在 [`server/prompt-registry.js`](../server/prompt-registry.js)，由 `server/prompt-contract.test.js` 逐条核对：改动提示词时如果不小心把安全边界、输出格式或四阶段定义改丢了，测试会直接失败。提示词迭代因此是可追溯、可回归的，而不是一次性的文案调整。

### 学情生成提示词

```text

输出要求：优先使用工具查询知识点和复习间隔；最终必须输出合法 JSON，不要 Markdown 代码围栏，字段为 radar([{name,value}])、plans([{id,name,subject,estimatedMinutes,priority,reviewTime,knowledgeTags,status,createdAt}])、explanation。reviewTime 使用毫秒时间戳。解释要说明安排原因和复习节点。
```

## MediaPipe Face Landmarker 端侧视觉检测

核心完整组件在 [`src/components/CameraMonitor.vue`](../src/components/CameraMonitor.vue)，纯函数在 `src/vision/`。实现顺序：默认 `enabled=false`；只有主动开关后显示说明并点击同意，才调用 `getUserMedia`；`@mediapipe/tasks-vision` 在同意后按需动态加载；WASM 和模型文件打包在 `public/mediapipe` 与 `public/models`，运行时不依赖外网 CDN。

每帧只跑一次 `FaceLandmarker.detectForVideo`（VIDEO 模式、最多 2 张脸、输出 blendshapes 与面部变换矩阵），在本地得到 478 关键点、头部欧拉角、眼睛开合与人脸框，再用纯函数计算状态：

- `src/vision/metrics.js`：blendshape 眨眼系数优先，缺失时用六点 EAR 兜底；从 4x4 列主序矩阵解出 yaw/pitch/roll。
- `src/vision/oneEuro.js`：对 yaw/pitch/eyeOpen/人脸占比做 One Euro 滤波，抑制抖动。
- `src/vision/attentionMachine.js`：状态机输出 `focused / looking-away / head-down / drowsy / multiple / away`。离岗需无人脸或人脸占比 <8% 持续 10 秒；多人 2 秒；犯困 1.5 秒；扭头 2 秒且 60 秒内累计 10 秒才提示；低头 5 秒只提示坐直。优先级 away > multiple > drowsy > looking-away > head-down > focused，进入/退出带迟滞，同类提示 60 秒冷却。

只有 `away` 会触发专注页暂停计时；分心、犯困、多人、低头只弹温和提示并写 `visualLogs`，不中断计时。组件每帧只更新内部状态，UI 与 `emit('status')` 最多 1Hz，避免 Vue 响应式拖慢推理。

性能与降级：目标 12–15fps，优先 `requestVideoFrameCallback`，回退 rAF；单帧耗时 EMA >40ms 降到 10fps、>80ms 降到 6fps、>150ms 自动切换到 BlazeFace 轻量模式（只保留在岗与多人）；轻量模型也失败时保留摄像头预览并提示模型错误。若 `face_landmarker.task` 加载失败，启动时直接回落 BlazeFace。

资源清理：

```js
function stopMonitoring() {
  running = false
  landmarker?.close?.()
  landmarker = null
  faceDetector?.close?.()
  faceDetector = null
  if (stream) stream.getTracks().forEach(track => track.stop())
  if (video.value) video.value.srcObject = null
}
```

页面卸载、路由离开、开关关闭和页面切到后台均停止采集/推理并释放 tracks。用户拒绝权限、无摄像头或低配模式时，转为页面可见性切换检测；基础倒计时继续可用。

## 背诵学习窗（文科记忆类计划）

学习计划里「背诵 / 默写 / 听写 / 单词 / 拼写」类任务不再直接进专注页，而是按科目 + 关键词分岔到 `/recite?planId=…&mode=…`：语文古诗文、英语课文走逐句背诵（`text`），英语单词走卡片速记（`words`），听写走走「中文提示 + TTS 发音 + 打字默写」（`dictation`）。判断逻辑在 `src/utils/reciteMode.js`（关键词驱动，学科只做辅助，化学方程式默写这类跨学科任务同样能识别），计划行上会显示对应小标签。

内容来源：`/api/agent/recite/content` 由 DeepSeek 按「学科 + 计划名 + 年级」生成原文或词表，失败时回落到 `server/recite.js` 的内置篇目。拿到内容先落一份 `confirmed:false` 的 `reciteContents` 缓存，用户确认（或手动改一次）后置 `confirmed:true`；下次同「学科 + 计划名」直接读缓存，只有未确认的才再次让用户过目，避免模型幻觉内容直接进背诵流程。

本地语音识别：`src/services/localAsr.js` 用 `@huggingface/transformers` 在浏览器里跑 `whisper-tiny`（encoder/decoder 均为 quantized ONNX，约 40MB），模型与推理内核分别放在 `public/models/Xenova/whisper-tiny` 与 `public/ort`，运行时关闭远程模型下载（`env.allowRemoteModels = false`），完全离线。麦克风按能量阈值切句，停嘴后送一小段音频识别，结果与当前句做字符级对齐（`src/utils/reciteAlign.js`），覆盖率达标才判过；连续 8 秒没有推进就浮出提示卡，先给首 4 字、再给 6 字递进，也可以跳过或改成打字核对。整句都是 ASCII 时才按英文识别，避免中文里夹字母被当成英语课文。

背诵时长计入专注：结束时按 `saveFocusSession` 的同一套字段写一条 `mode:'recite'` 的记录，并标记 `sampled:false`（没有摄像头采样），看板按只读时长降级展示。卡壳的句子、没记住的单词、听写错的词通过 `src/utils/reciteMistakes.js` 写进 `mistakes`（`source:'recite'`、`type:'recite'`），同一个错处固定 id，再卡壳只累加错次并清掉消灭标记，错题库里按「背诵练习」来源可筛，复习弹窗走「我做对了 / 还是不会」自评流。

## 学习计划统一分流（练习做题 / 背诵 / 错题复习）

所有学习计划点击后**不再进入专注空间**，改由 `src/utils/planRoute.js` 的 `detectPlanTask(plan)` 统一分流，按优先级：① 名称含「错题 / 易错 / 重做 / 订正」→ `/mistakes?subject=…&filter=open`（错题复习）；② 背诵 / 单词 / 听写 → `/recite`（复用 `detectReciteMode`）；③ 其余（练习、复习、知识点，含默认）→ `/practice`（练习做题）。计划行上的小标签用 `planTaskBadge` 显示「做题 / 背诵 / 背单词 / 打字默写 / 复习错题」。

练习做题窗 `/practice?planId=…`（`src/views/PracticeView.vue`）**纯本地出题，不调模型**：`/api/practice/generate`（`server/practice.js`）按「计划名 → `searchCurriculum` 匹配章节 → `pickBankQuestions`/`pickQuizBankQuestions` 抽离线题库」秒出题，题量从计划名解析（「8 道练习」出 8 题），题库没命中的题位用本地兜底补齐。客观题自动判分、解答题自评，`computeQuizSummary`/`gradeQuestion` 复用章节测试口径；答错的题写 `mistakes`（`source:'practice'`），复用错题库复习与消灭机制。题库文件在 `server/data/question-bank/`（客观题）与 `server/data/quiz-bank/`（主观题），按「年级/科目/版本/章节」组织，随项目分发、离线可用。

## OCR、接口与降级

OCR 用 Tesseract.js 在前端执行，照片不上传到后端；用户确认后也可以把压缩后的题目图以 base64 发送给 DeepSeek `deepseek-flash` 做多模态答疑，图片不写入本地会话历史。后端 `/api/agent/diagnose` 校验必填问卷，并先调用 RAG 工具；`/api/agent/assessment/generate` 按选中专题生成原创摸底题；`/api/agent/iterate` 读取本地反馈聚合上下文并产出更新计划；`/api/agent/tutor` 执行文字/图片答疑、提示词和内容兜底过滤。所有模型请求设置超时，错误结果使用本地 mock 学习计划、专题自评题或引导文案。

## AI 输出的可解释性与一致性校验

三条机制把"模型说了算"变成"可核对、可追溯、可降级可见"：

**一、决策来源徽章。** `src/components/SourceBadge.vue` 按 `analysisSource` / `source` 把结论区分为「模型判断」「本地规则」「真题检索」三种来源。错题归因在模型不可用时会静默降级到本地关键词规则——降级本身必须让用户看见，否则"看起来是 AI 在判断"就成了误导。徽章还带 title 说明判定依据。

**二、提示词契约。** `server/prompt-registry.js` 登记全部 11 条提示词的版本、用途与必需条款，`server/prompt-contract.test.js` 逐条核对：安全边界、JSON 输出格式、四阶段定义、逐项解析格式等条款都不能在改写中丢掉。改提示词从此是可回归的工程动作，而不是文案调整。

**三、周报数字一致性校验。** `server/weekly-report.js` 的 `verifyWeeklyReportNumbers` 从周报正文里逐个抠出关键指标（专注分钟、专注次数、测试次数、正确率、消灭/新增错题、重做次数、计划完成条数），与前端传入的真实聚合数据逐项比对，容差 ±1（口径四舍五入），并跳过"正确率**到** 80%"这类目标值。命中的不一致项随周报一起返回，界面上直接标红说明"写成 X、实际 Y"。这把周报提示词里的"禁止编造"从口号变成了可执行的兜底。

**四、RAG 检索质量可量化。** `server/rag/rag-eval-cases.js` 是 23 条"提问 → 应命中真题"的评测集，`npm run rag:eval` 输出学科命中率、关键词命中率、Top-1 平均得分与未通过明细；`server/rag.eval.test.js` 把它接进 `npm test`，改动分词或权重后检索一旦退化就会红。评测集还暴露并修掉了一个真实缺陷：查询分词原先对整条文本（含英文数字）做 2~3 字滑窗，会把无意义查询切成 `xx`/`xxx` 这类跨边界垃圾词元，而稀有词元在 BM25 里 IDF 更高，反而能硬凑出高分结果；现在同字符重复的词元被丢弃，无意义查询不再返回片段。

## 混合检索：双路召回 + RRF 融合（默认关闭，附评测结论）

`server/rag/dense.js` + `server/rag/hybrid.js` 实现了标准的**稀疏 + 稠密双路召回 + RRF 融合**：`searchPassages`（BM25）负责"命中明确关键词"，稠密通道负责"说法不同但语义相近"，两路按排名倒数加权融合（RRF K=60，只看排名不看分数绝对值，因此两路分数量纲不同也不会互相干扰）。

**稠密通道为什么不用神经网络 embedding**：项目里只有浏览器版的 `onnxruntime-web`，服务端要跑 ONNX 得装 `onnxruntime-node`，首次加载模型会拖慢接口、增加内存占用，与"不能影响正常使用"冲突。因此稠密通道改成零依赖的纯 JS 实现：中文汉字串 2-gram + 英文整词做特征，hashing trick 压成 2048 维定长稠密向量，TF-IDF 加权后 L2 归一化，检索时算余弦。向量索引由 `npm run rag:build-vector` 离线构建（1.2MB，659ms），运行时只做点积，**毫秒级**。

**安全约束（不影响正常使用的四条）**：

1. 稠密索引文件缺失、损坏或加载失败 → 直接退回纯 BM25，接口行为与改造前完全一致；
2. 稠密通道运行时抛错 → 熔断该通道，进程内后续请求都走 BM25；
3. 稠密索引只在进程内缓存，读取失败不抛到调用方；
4. `rag_knowledge_query` 工具**默认仍走 BM25**，需显式设置 `RAG_HYBRID=1` 才启用融合。

**评测结论（`npm run rag:compare`）**：23 条用例下两路指标持平（学科命中 100%、关键词命中 100%），用改写型查询（如"为什么夏天比冬天热""古诗里劝人珍惜时间的句子"）对比时，混合路在个别查询上还把无关试卷说明排到了前面。原因是**字符级词项向量与 BM25 同源，都是字面词元匹配，对"换一种说法"没有语义增益**。

因此结论是：**默认不启用**。这个判断本身就是评测集的价值——它让团队能"用数据否决一个看起来更高级的方案"，避免为了展示混合检索而牺牲答疑引用质量。混合检索保留为完整可用的能力（`RAG_HYBRID=1`），等接入真正的句向量模型后再用同一把评测尺子复测。

## MCP 服务的三类能力

`server/mcp.js` 对外暴露 **Tools / Resources / Prompts** 三类能力，全部与 Web 端 Agent 共用同一套实现（`executeTool`、课标目录、RAG 检索），不会出现"两套口径"：

- **Tools**（动作）：`search_curriculum`、`calc_review_interval`、`list_curriculum_chapters`。专注记录与视觉状态由浏览器推送，**不在协议层伪装成可用工具**，避免外部调用拿到永远为空的假数据。
- **Resources**（数据）：`ai-teach://curriculum/subjects`、`ai-teach://curriculum/chapters/{grade}/{subject}`、`ai-teach://exam/passages/{subject}`。外部 Agent 读资源不用自己拼查询参数，省 token 也更不容易用错口径。
- **Prompts**（工作流模板）：`explain_mistake`、`plan_next_week`、`tutor_guide`。这三个模板与项目内部 Agent 同口径，外部 Agent 无需重新发明指令。

`server/mcp.integration.test.js` 用真实 MCP 客户端连一次 stdio 服务，验证三类能力可发现、可读取、可生成——不是只断言代码里有这些字段。

## 走神实时干预（分心 / 低头 / 犯困 → 渐进提示 → 暂停计时）

原实现里，**离岗**（画面里没有人）会暂停计时并弹窗，而**分心、低头、犯困**只弹一条温和提示、不打断计时。这在真实场景下不够：人坐在屏幕前但心思飘走，计时照走，最后看板显示"专注 25 分钟"，实际效率很低。

`src/utils/attentionIntervene.js` 补上这一段，做成**三段式渐进干预**，而不是检测到就打断：

| 阶段 | 触发条件 | 表现 |
| --- | --- | --- |
| none | 刚出现异常状态 | 沿用原有的温和提示弹窗，不打扰 |
| warn | 距阈值不足 8 秒 | 专注页圆环上方出现橙色倒计时条："分心中 · 5 秒后自动暂停计时" |
| intervene | 超过阈值 | 暂停计时 + 弹窗说明原因与建议，按钮变为「继续」 |

**阈值按状态分级**，因为误判代价不同：低头 60 秒、写题时低头是常态不能太敏感；分心 30 秒；犯困 20 秒（最明确的问题）。同一轮异常只干预一次，等状态回到专注才允许下一次，避免连续弹窗。重新开始或继续专注时计数重置——刚被打断不等于现在还在走神。

**统计口径不被污染**：看板只认 `focus / distracted / away / unknown` 四种分段类型，因此 `attentionSegmentType()` 负责把 `looking-away / head-down / drowsy / multiple` 统一映射成分类的 `distracted`，具体是哪一种只写进视觉明细日志（`saveVisualLog`）。若直接把明细类型写进分段统计，看板上的走神时长会算乱。

判定逻辑是纯函数（不依赖 DOM 与计时器），`src/utils/attentionIntervene.test.js` 覆盖阈值分级、渐进提示、只触发一次、状态恢复后重置、分段口径映射共 9 条用例。
